## 二、A 组：设计建议逐项结论

### A1. 主体内容进一步结构化

**原建议**

把 `subject_content` 从自由文本进一步拆成角色、武器、玩偶、场景、道具等层级，并建立互斥规则。

**考虑**

- 一个素材经常同时包含人物、武器、载具、道具和环境，类别天然不互斥。
- 固定层级无法覆盖不同行业和项目中的未知主体类型。
- 如果拆成新的向量通道，会增加入库 Embedding、Milvus 存储、聚类任务和搜索通路。
- 但区分画面中的主要实体和次要实体，对主体描述和簇标题确实有价值。

**采用方式**

在现有 `subject_content` 内增加开放的自然语言结构：

```json
{
  "primary_entity": "手持长刀的男性角色",
  "secondary_entities": ["长刀", "燃烧车辆", "废墟街道"]
}
```

两部分共同形成一个主体描述，并只生成一个 `subject_content` 向量；不建立固定枚举和互斥本体。

> **最终判断｜🟡 调整后接受**

### A2. 场景主题拆成固定子场景

**原建议**

先判断素材是否为环境场景，再分为竞技场、餐饮、街道、梦幻背景等子类。

**考虑**

- “是否适用场景主题”的判断是必要的，局部主体特写不应被强行赋予完整场景。
- 固定子场景只能覆盖示例数据，无法适配游戏、美术、影视、工业、建筑等不同工作区。
- 增加子场景向量或分支聚类会增加成本，也会让边界样本更难处理。
- 当前更重要的问题是让 `scene_theme` 描述整体环境、时间、事件和叙事情境，而不是再次描述主体。

**采用方式**

保留一个 `scene_theme` 通道，允许 `not_applicable`；通过更清楚的维度定义提高描述质量，不增加固定子类。

> **最终判断｜🟡 调整后接受**：接受“适用性判断”，拒绝固定场景本体和新增通道。

### A3. 视觉风格拆成媒介、材质、渲染和审美层级

**原建议**

把 `visual_style` 拆成媒介、材质、渲染方式和审美风格等更细层级。

**考虑**

- 这些属性可以帮助模型写出更准确的风格描述。
- 它们经常同时存在且边界模糊，不适合成为互斥类别。
- 每层独立生成向量，会直接增加入库、聚类和多维搜索成本。
- 对未覆盖的新媒介和新风格，封闭分类会快速失效。

**采用方式**

继续使用一个 `visual_style` 描述和向量；提示模型在适用时自然表达媒介、材质、渲染表现和审美特征，不建立固定字段树。

> **最终判断｜🟡 调整后接受**：接受描述层面的丰富，拒绝新增向量维度和封闭层级。

### A4. 色彩与构图拆成两个独立维度

**原建议**

把 `color_composition` 拆成 `color_palette` 和 `composition`，并加入冷暖色常识门。

**考虑**

- 色彩和构图确实是不同问题，拆分可能减少两种信息互相干扰。
- 但拆分后每个 Asset 至少增加一个描述、一个 Embedding、一个 Milvus 通道和一个独立聚类状态。
- 搜索同时选择两个通道时还会增加查询向量和召回融合开销。
- 目前没有消融实验能证明收益足以覆盖持续成本。
- 冷暖色只能作为描述内容，不能覆盖全部配色体系。

**采用方式**

当前保留 `color_composition` 单通道，在描述内部清楚表达颜色与构图。只有真实检索数据证明二者互相污染严重时，才重新测试拆分方案。

> **最终判断｜⏸️ 暂不接受**：保留为未来可验证假设，不进入当前实现。

### A5. 氛围只保留有画面证据的内容

**原建议**

`mood_atmosphere` 只表达画面可支持的氛围，避免把无法观察的心理状态当成事实。

**考虑**

- 这能降低幻觉和过度解释。
- 不需要新增模型调用、向量或搜索通路，只需要调整现有维度提示词。
- 氛围本身可以是整体观感，不必被限制为固定情绪词表。

**采用方式**

保留现有 `mood_atmosphere`，要求基于画面线索自然描述；证据不足时使用不确定表达或 `not_applicable`。

> **最终判断｜✅ 接受**

### A6. 人物动作与心理状态分离

**原建议**

把可见姿态放入 composition/pose，把心理状态设为 unknown 或交给人工标注。

**考虑**

- 姿态是可观察信息，心理状态通常只是推断，二者可信度不同。
- 新增独立 pose 通道会增加聚类和搜索成本。
- 完全删除心理描述也会损失部分用户确实需要的情绪或叙事信息。

**采用方式**

不新增 pose 向量。现有 `character_state_or_psychology` 优先描述姿态、动作和可见状态；心理含义只有在画面线索充分时才以较谨慎的方式表达。

> **最终判断｜🟡 调整后接受**：接受事实与推断的区分，不接受新增独立向量维度。

### A7. 将版本、衍生和生成来源放入关系图

**原建议**

版本、衍生、生成来源等方向关系不再进行无向聚类，改成关系图中的有向边。

**考虑**

- 概念上正确：`A derived_from B` 与“两个文件语义相似”不是同一问题。
- 真正困难的是关系证据来源、方向和可靠性，而不是图数据结构或前端画布。
- 对参考代码的检查表明，它只预置了若干 `Relation` 数据，支持展示、确认/拒绝和 BFS 查询；导入新 Asset 时不会自动生成关系，也没有实现候选发现、关系分类和自动建边。
- 文件名、路径、时间和视觉相似度只能形成候选，不能单独证明版本或衍生关系。

**可能成立的可靠证据**

- 创作软件或工程文件中的引用记录。
- 系统自身保存的生成任务、Prompt ID 和输出 Asset ID。
- 用户在系统内执行复制、衍生、生成、替换等操作产生的事件。
- 文件历史或版本管理记录。
- 用户确认后的关系。

**采用方式**

先保留关系数据模型的方向性设计，不建设自动关系图。只有来源、方向、证据、置信度和确认状态能够明确记录时再实施。

> **最终判断｜⏸️ 方向接受，实现暂缓**

### A8. 自动识别文件家族 `filename_family`

**原建议**

通过文件名、路径、版本号和相似性识别同一文件家族，并将其作为独立通路。

**考虑**

- 不同用户的命名习惯差异极大，UUID、中文描述、日期后缀、软件自动命名都可能出现。
- 即使文件名、目录、时间和视觉相似度一致，也只能得到候选，不能稳定证明属于同一家族。
- 不能要求用户主动维护大量家族标签。
- 错误家族关系可能反过来污染检索和版本判断。

**采用方式**

不建设正式 `filename_family` 聚类维度，不让弱推断直接改变成员关系。未来可把它作为内部候选信号单独测试。

> **最终判断｜⏸️ 暂缓**：不进入当前方案。

### A9. 按维度生成簇标题和描述

**原建议**

每个簇标题只回答当前聚类维度的问题，避免把主体、色彩、构图和氛围混在一个标题中。

**考虑**

当前系统已经按聚类维度生成针对性簇标题和描述。

**采用方式**

维持现状，后续只做质量测试，不重复开发。

> **最终判断｜✔️ 已实现**

### A10. 将搜索拆成大量独立召回路径

**原建议**

并行执行精确、BM25、语义、视觉、字段、参考一致性和关系图等多条召回，再统一融合。

**考虑**

- 多路召回理论上提高覆盖率，但每增加一路都会增加查询、融合、调试和解释成本。
- 当前系统已经存在多维向量召回，再继续扩张通路会明显增加延迟。
- 文件名、专有名词、Prompt 原文和稀有关键词确实是向量召回的弱项。
- 关系召回在关系图没有可靠建边流程前没有可用数据基础。

**采用方式**

最多保留两类召回：

1. 当前 Milvus 多维向量召回。
2. 一次统一的本地文字召回，覆盖文件名、路径、原始文本、描述和全文/BM25。

本地文字召回必须先用测试集证明增益；关系召回暂不接入。

> **最终判断｜🟡 调整后接受**：接受补充文字召回，拒绝大量并行通路。

## 三、B 组：实施方案逐项结论

### B1. 盲候选分组后再进行组内 Understanding

**原建议**

先对素材做不带业务标签的候选分组，再让模型在组内对比并生成结构化逐图事实，最后继续按维度聚类。

**考虑**

- 第一次候选分组依赖的向量、阈值和重叠规则没有明确方案。
- 初始分组错误后，组内 Understanding 无法看到组外相关样本。
- 需要额外一轮分组和组级模型调用，随后仍然要做按维度聚类，形成重复计算。
- 新 Asset 的增量流程也会变得复杂：既要维护候选组，又要维护正式簇。

**采用方式**

继续使用“逐 Asset Understanding → 生成各维度原始向量 → 按维度聚类”的主流程。

> **最终判断｜❌ 拒绝**

### B2. 主体采用层级互斥和角色存在性硬门

**原建议**

人物、武器、玩偶、场景和道具等层级互斥，并用角色存在性阻断跨类污染。

**考虑**

- 目标是解决“武器图中出现人物后被归入人物簇”的污染问题，这个问题真实存在。
- 但复杂画面中的实体并不互斥，固定硬门会制造新的错误。
- 主体层级还会因职业和项目变化而变化，不具有通用性。

**采用方式**

只采用 A1 的“主要实体 + 次要实体”开放结构；不建立全局互斥类别和角色硬门。

> **最终判断｜🟡 调整后接受**

### B3. 场景先硬判断，再进入固定子场景聚类

**原建议**

先判断是否为环境场景，再进入竞技场、街道、餐饮、梦幻背景等分支。

**考虑**

- `not_applicable` 可以避免主体特写被强行描述为场景。
- 固定子场景对未知内容覆盖不足，且每个分支的样本密度可能过低。
- 最终仍然需要在 `scene_theme` 维度上组织素材，没有必要增加一层封闭分类。

**采用方式**

保留 `not_applicable` 和清晰的场景定义，不建立固定子场景。

> **最终判断｜🟡 调整后接受**

### B4. 风格建立固定媒介—材质—渲染层级

**原建议**

对风格建立结构化层级，再按层级组织或检索。

**考虑**

- 同一素材可能同时具有摄影、数字绘画、3D 渲染、胶片质感和特定审美风格。
- 强制层级化会让混合媒介和新风格难以表达。
- 作为独立搜索和聚类通路时成本过高。

**采用方式**

只在一个 `visual_style` 自然语言描述中表达适用信息，不建立固定层级。

> **最终判断｜❌ 拒绝固定层级；🟡 接受描述优化**

### B5. 为色彩、心理、用途和受众建立细粒度规则与状态

**原建议**

对冷暖色、心理状态、用途、受众、来源和版权等字段建立更细的规则，并按 confirmed、inferred、unknown 分层。

**考虑**

- “确定事实与模型推断不能等价”这一原则正确。
- 但一次性为所有字段增加状态，会扩张 Understanding Schema、数据库、前端、过滤和历史数据迁移。
- 固定冷暖色或用途枚举无法覆盖未知项目。
- 版权、作者等高风险事实没有权威元数据时，不应由模型推断。

**采用方式**

- 当前只在描述层面降低无证据断言。
- 版权、作者等无权威数据时保持未知，不纳入视觉聚类。
- 暂不建设覆盖所有字段的通用证据状态体系。

> **最终判断｜⏸️ 原则接受，系统化实现暂缓**

### B6. 使用 Complete-link 解决相似度桥接

**原建议**

在纯视觉相似组中使用 Complete-link，新成员必须与组内每个成员兼容，以避免 `A≈B、B≈C` 把 A 和 C 串成同一簇。

**考虑**

- 它可能减少密度聚类中的桥接错误。
- 它对离群点敏感，可能产生大量小碎片组。
- 全局两两距离成本较高，不适合直接替换现有 HDBSCAN。
- 是否有效必须在真实数据上比较桥接错误、碎片率、噪声率、稳定性和耗时。

**采用方式**

作为独立离线实验：`ANN 候选邻域 + 局部 Complete-link`，不替换当前全局 PCA + HDBSCAN 流程，也不混入当前四参数网格。

> **最终判断｜🧪 进入实验**

### B7. 两成员业务 Capsule 与有向关系边

**原建议**

允许只有两个成员的业务组；角色—武器、版本、衍生和 Prompt 生成来源使用有向边表达。

**考虑**

- 两张重复图、近似版本或高度相似素材可以形成有价值的 `similarity_group`。
- 角色—武器等属于业务关系，不应为了满足 `min_cluster_size` 被伪装成语义簇。
- 但当前无法可靠自动确定角色—武器、版本和衍生关系；参考代码同样没有解决自动建边。
- 不能仅为二元关系把 HDBSCAN 的 `min_cluster_size` 全局降到 2。

**采用方式**

概念上区分：

- `semantic_cluster`：现有语义聚类簇。
- `similarity_group`：重复图、近似版本或高度相似素材组。
- `relation_edge`：版本、衍生、生成和业务关系。

暂不实现自动关系边；`similarity_group` 只进入独立价值评估。

> **最终判断｜⏸️ 概念接受，实现暂缓**

### B8. confirmed / inferred / unknown 驱动硬过滤

**原建议**

将字段分成已确认、模型推断和未知，并让已确认字段参与硬过滤，推断字段用于软排序。

**考虑**

- 这是完整的证据治理和搜索语义设计，不是一个简单字段改动。
- 需要定义每类字段的证据来源、冲突处理、用户纠正、历史迁移和失效机制。
- 当前 Understanding 大部分来自模型；如果直接把模型输出包装为硬事实，会产生错误过滤和空结果。
- 它与本轮聚类参数选择无直接关系，会显著扩张开发范围。

**采用方式**

本轮不实施。未来如果建设关系与证据系统，再统一设计状态、来源和硬过滤规则。

> **最终判断｜⏸️ 暂缓**

## 四、对当前系统的最终决策

### 立即保留或实施

- 保持现有向量维度数量，不继续拆分新通道。
- 在 `subject_content` 内表达主要实体和次要实体，仍只生成一个主体向量。
- 保持 `scene_theme` 的整体环境、时间、事件和叙事情境定义，并允许 `not_applicable`。
- 优化氛围和人物状态描述，减少无证据的心理断言。
- 维持现有按维度生成簇标题和描述的实现。

### 进入独立实验

- 一条统一的本地文字召回，验证它对文件名、路径、专有名词、Prompt 和原始文本的增益。
- `ANN 候选邻域 + 局部 Complete-link`，评估桥接错误、碎片率、噪声率、稳定性和耗时。
- 两成员 `similarity_group` 的业务价值与识别边界。

### 暂缓

- 自动版本、衍生、生成来源和角色关系图。
- `filename_family` 文件家族推断。
- 覆盖所有字段的 confirmed / inferred / unknown 证据体系与硬过滤。

### 拒绝

- 把现有维度继续拆成大量独立向量通道。
- 固定且封闭的主体、场景、色彩和风格类别体系。
- 盲候选分组后再进行组内 Understanding。
- 用全局 Complete-link 替换 HDBSCAN。
- 把二元关系伪装成语义聚类簇。
- 同时增加大量并行召回路径。

## 五、对 PCA/HDBSCAN 实验的影响

当前参数实验维持四个变量：

```text
PCA 目标维度
min_cluster_size
min_samples
cluster_selection_epsilon
```

`cluster_selection_method` 固定为 `eom`；融合权重和语义合并阈值先固定。

局部 Complete-link 必须作为另一组算法实验，不能混入上述四参数网格，否则无法判断指标变化来自 PCA/HDBSCAN 参数，还是来自聚类算法变化。

## 六、总结论

两份方案指出的问题大多真实存在，包括维度污染、心理推断、相似度桥接、文件名线索、二元关系和向量搜索对专有词召回不足。但原方案倾向于通过继续拆维度、建立封闭类别、增加中间分组、多路召回和关系图同时解决，整体复杂度和长期成本过高。

当前最合适的路线不是扩张系统，而是先把已有维度的语义边界描述准确，并完成真实数据下的 PCA/HDBSCAN 参数基线。主体只增加“主要实体、次要实体”的内部表达；搜索最多评估一条统一的本地文字召回；Complete-link 只做独立实验。

关系图的概念方向成立，但现阶段没有自动建图所需的可靠证据链。参考代码也只演示了预置关系的保存、展示、确认和遍历，没有实现自动发现与建边。因此关系图、文件家族和二元业务关系均不应直接进入当前生产方案，必须等待可验证的数据来源和独立实验结果。
